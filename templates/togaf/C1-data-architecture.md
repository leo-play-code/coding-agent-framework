# 階段 C1:資料架構 (Data Architecture)

> ADM 階段 C(子領域 1)｜目的:定義企業資料的管理、結構與儲存方式。

## 目的 (Objectives)
- 發展目標資料架構。
- 對基準(現況)與目標進行差距分析。

## 輸入 (Inputs)
- 業務架構(來自階段 B)。
- **`srs.md`(逆向工程產出)→ 作為現況資料架構 (Baseline) 的來源**,尤其其「5. 資料模型」章節。
- **`docs/prd/PRD_Data.md` → 作為目標資料架構 (Target) 的來源**(資料實體、SQL 慣例、約束、索引);本階段只做 gap,不重抄 PRD 細節。
- 架構原則、資料參考模型。

## 主要活動 (Steps)
1. 選定參考模型/視角/工具。
2. 由 `srs.md` 整理基準(現況)資料架構。
3. 發展目標資料架構。
4. 差距分析 (Baseline → Target)。
5. 解析影響、利害關係人審查。

## 產出物 (Deliverables)
- 架構定義文件(資料章節)。
- 架構需求規格(資料相關需求)。
- 資料架構的路線圖組件。
