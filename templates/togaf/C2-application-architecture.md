# 階段 C2:應用架構 (Application Architecture)

> ADM 階段 C(子領域 2)｜目的:規劃業務所需的軟體應用系統及其互動關聯。

## 目的 (Objectives)
- 發展目標應用架構。
- 對基準(現況)與目標進行差距分析。

## 輸入 (Inputs)
- 業務架構(來自階段 B)、資料架構(來自階段 C1)。
- **`srs.md`(逆向工程產出)→ 作為現況應用架構 (Baseline) 的來源**,尤其其「4. 外部介面與整合」與「6. 架構」章節。
- **`docs/prd/PRD_Application.md` + `PRD_API.md` → 作為目標應用架構 (Target) 的來源**;本階段只做 gap,不重抄 PRD 細節。
- 架構原則、應用參考模型。

## 主要活動 (Steps)
1. 選定參考模型/視角/工具。
2. 由 `srs.md` 整理基準(現況)應用架構。
3. 發展目標應用架構。
4. 差距分析 (Baseline → Target)。
5. 解析影響、利害關係人審查。

## 產出物 (Deliverables)
- 架構定義文件(應用章節)。
- 架構需求規格(應用相關需求)。
- 應用架構的路線圖組件。
