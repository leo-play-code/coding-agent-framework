# 軟體需求規格(逆向工程版)SRS — Reverse-Engineered

> 用途:指向一個**既有的程式碼/系統**,反推並記錄它「實際上做了什麼、隱含了什麼需求、用什麼架構」。
> 與正向 SRS 不同,本模板以「**觀察到的事實 → 推回的需求**」為核心,並明確標示**信心程度**與**待確認**之處。
>
> **流程定位:本文件記錄「現況」,是 TOGAF 的 Baseline 起點。** 先逆向工程產出本 SRS,再作為 TOGAF ADM 各階段的**現況 (Baseline) 輸入**(對應關係見 §9 與 [`togaf/README.md`](togaf/README.md))。
> **與 PRD 的分工:srs = 現況(系統實際做了什麼);[`prd/`](prd/README.md) = 目標(要做成什麼樣,含 SQL 慣例/前端)。** 兩者互補,由 TOGAF 各階段做 gap 分析。
>
> 標記慣例:`[事實]` 直接從程式碼/設定/行為觀察到;`[推論]` 由事實推回的需求;`[假設]` 尚未證實;`❓待確認` 需找人/文件確認。
