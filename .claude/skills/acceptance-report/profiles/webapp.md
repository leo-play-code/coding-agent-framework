# profile: webapp — 一般 web app 功能(對 UI 行為清單)

適用:一般網頁功能(表單、流程、互動),非逐格報表也非純 API。基準 = **PM 的 UI 驗收清單**。

## 驗收準則來源(acceptance[])
從使用者故事/PM 清單抽出**逐步驟可操作的 UI 行為**:
- 來源:PM 驗收清單 / 使用者故事 / `page.tsx` 的互動與狀態。
- 每條 = 一段使用者操作路徑 + 預期畫面結果:
  - 主流程:「加入購物車 → 結帳 → 付款成功頁」
  - 前置守衛:「購物車為空時不可進入結帳」
  - 計算/狀態:「套用折扣碼後金額正確」
  - 錯誤回饋:「付款失敗顯示錯誤且不建立訂單」
- `surface` = 路由;`writes` 標建立訂單/金流/寄信等副作用。

## 驗證基準與策略(verification)
- `baseline`:PM 提供的驗收清單(N 條主要流程)。
- `strategy`:`qa` skill 逐步驟實際操作 + 每步截圖存 `verification.screenshots`(如 `docs/acceptance/shots/checkout/`);關鍵流程可加 `verify` 端到端。
- 提升證據力:
  - **A** — `qa` 把每條流程實際點過通過並截圖存證。
  - **B** — 有 E2E/元件測試綠,但未人工逐步驟走。
  - **C** — 僅實作完成。

## 常見坑
- 截圖要對得上準則(哪張圖證明哪條),存進 `shots/<功能>/`。
- 前置守衛與錯誤回饋最常漏 → 每功能至少一條負向準則。
